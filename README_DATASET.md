# PlantAdvisor — датасет и обучение v3

## Запуск в Google Colab

1. Откройте [03_training_and_evaluation_v3.ipynb в Colab](https://colab.research.google.com/github/Batyaoftheyear/plant-advisor/blob/main/notebooks/03_training_and_evaluation_v3.ipynb).
2. Выберите **Среда выполнения → Сменить среду выполнения → GPU T4** и выполните ячейки по порядку. Если установка пакетов потребует перезапуска среды, перезапустите её и начните выполнение заново.
3. В окне `drive.mount` выберите свой Google-аккаунт и разрешите подключение Google Drive. Пароли и токены не вписываются в ячейки: GitHub и исходные модели общедоступны.
4. Ячейка настройки сама синхронизирует входные файлы из GitHub. Ручная загрузка JSONL или ZIP на Drive не требуется. После проверки данных начинается обучение.

Третий ноутбук ещё не содержит выполненного GPU-прогона; метрики и веса не представлены как уже полученный результат.

## Автоматическая синхронизация

`scripts/sync_colab_data.py` разрешает `GITHUB_REF` в один полный SHA коммита, читает `data/v3/manifest.json` и сверяет размер и SHA-256 всех 12 входных файлов. Ноутбук загружает и сам модуль синхронизации из этого же коммита. Загружаются:

- пять файлов набора из `data/v3/`;
- неизменный `data/eval_questions.jsonl`;
- конфигурация и 30 ответов baseline;
- конфигурация модели-судьи v2;
- три предоставленных отчёта аудита v3.

Данные v1/v2 в общей папке `data/` не заменяются. Совпадающие файлы не скачиваются повторно. Если общий контрольный файл на Drive отличается от GitHub, синхронизация останавливается до записи новых данных. Изменяемые файлы внутри каталогов v3 предварительно копируются в `sync_backups/v3/<время>/`. Файлы, отсутствующие в манифесте, не удаляются.

На Drive сохраняется `data/v3/sync_receipt.json` с SHA коммита и результатом загрузки. Для повторения конкретного снимка замените `GITHUB_REF = "main"` полным SHA из этой квитанции. При недоступности GitHub повторите запуск после восстановления подключения; переключение на устаревшие данные автоматически не выполняется.

## Размещение версий и результатов

| Материалы | Каталог |
|---|---|
| Исходные данные v1 | `data/sft_metadata_raw.jsonl` |
| Сохранённый набор v2 | `data/train.jsonl`, `data/validation.jsonl`, сопроводительные файлы в `data/` |
| Набор v3 | `data/v3/` |
| Выполненные прежние ноутбуки | `notebooks/01_baseline_and_judge.ipynb`, `notebooks/02_dataset.ipynb` |
| Проверка v3 | `notebooks/02_dataset_v3.ipynb`, `results/dataset/v3/` |
| Обучение v3 | `notebooks/03_training_and_evaluation_v3.ipynb` |
| Адаптер, точки сохранения и логи v3 на Drive | `results/sft/qwen25_3b_qlora_dataset_v3/` |
| Ответы, судья и сравнение v3 на Drive | `results/evaluation/qlora_dataset_v3/` |

Старые `results/sft/qwen25_3b_qlora_v2/` и `results/evaluation/qlora_v2/` не затрагиваются. Завершённый адаптер v3 используется повторно только при совпадении сохранённой конфигурации и хешей данных; адаптер v2 не подставляется в этот эксперимент.

Параметры v3: 2 эпохи, LR `3e-5`, LoRA `r=16`, `alpha=32`, dropout `0.10`, эффективный batch size 8. Валидация и сохранение выполняются каждые 15 шагов; лучшая точка выбирается по `eval_loss`. Для сравнения baseline и SFT оцениваются одним судьёй заново; исходные оценки первого этапа остаются сохранёнными.

## Проверка и повторная сборка

Из корня локального репозитория, без GPU:

```bash
python scripts/audit_sft_v3.py
python scripts/sync_colab_data.py --project-root . --verify-local
python -m unittest discover -s tests -v
```

Для намеренной повторной сборки v3:

```bash
python scripts/build_sft_v3.py
python scripts/update_v3_manifest.py
python scripts/audit_sft_v3.py
```

Сборщик записывает только `data/v3/` и `results/dataset/v3/`. Из `scripts/build_sft_dataset.py` читается таблица растений через AST; старый генератор при этом не выполняется. Остальные скрипты первоначального формирования и ревизии включены из архива как материалы предыдущего процесса и не вызываются ноутбуком v3.

Набор содержит 400 синтетических диалогов, 25 растений и 141 семейство сценариев. Полная экспертная проверка не выполнена. Подробности: [карточка v3](docs/v3/DATASET_CARD.md), [отчёт ревизии](docs/v3/REVISION_REPORT.md). Веса, кеши, квитанции синхронизации и резервные копии не добавляются в GitHub.
