# Воспроизведение PlantAdvisor v3

## Сохранённый эксперимент

`notebooks/03_training_and_evaluation_v3.ipynb` содержит выполненный прогон на T4: 90 шагов, 2 эпохи, 30 ответов SFT и сравнение на 29 общих оценках судьи. Все выводы сохранены. Конфигурация, окружение и квитанция GitHub загружены с Drive; хеши train, validation и манифеста совпадают с `data/v3/`.

На Drive не обнаружены финальный адаптер, полные JSONL сравнения и завершённые логи. Экспортированные из ноутбука таблицы и изображения помечены префиксом `notebook_` или суффиксом `_notebook`; они не обозначают восстановление отсутствующих исходных файлов.

## Получить веса и полный архив

[Откройте 04_reproduce_v3.ipynb в Google Colab](https://colab.research.google.com/github/Batyaoftheyear/plant-advisor/blob/main/notebooks/04_reproduce_v3.ipynb).

1. Выберите T4 и выполните ячейки по порядку. Если установка библиотек потребует перезапуска, перезапустите среду и начните выполнение заново.
2. В окне `drive.mount` разрешите подключение Google Drive. GitHub и исходные модели общедоступны; секреты в коде не используются.
3. Сохраните `plant_advisor_v3_reproduction_training.zip`, который скачивается после обучения и построения loss. В нём уже находятся `adapter_model.safetensors`, `adapter_config.json`, конфигурация и журналы.
4. После оценки сохраните `plant_advisor_v3_reproduction_complete.zip`. Он дополнительно содержит 30 SFT-ответов, оценки судьи, таблицы и графики. Поместите полный архив в рабочую папку проекта для проверки и публикации артефактов.

Выходы воспроизведения записываются в `/content/plant-advisor-v3-reproduction/`, подкаталоги `results/sft/qwen25_3b_qlora_dataset_v3_recovery/` и `results/evaluation/qlora_dataset_v3_recovery/`. Старые эксперименты не заменяются. Этот локальный диск временный: ZIP необходимо сохранить на компьютере до завершения сеанса. Веса нового запуска нельзя выдавать за сохранившиеся веса первого прогона; новый результат имеет отдельное происхождение.

Экспорт выполняется `scripts/export_submission_artifacts.py`. Перед упаковкой проверяются наличие адаптера и согласованность данных с конфигурацией. В ZIP включаются контрольные суммы; промежуточные checkpoints и состояния оптимизатора не включаются.

## Входные файлы

Синхронизация использует один SHA коммита и `data/v3/manifest.json`. Загружаются пять файлов v3, контрольные вопросы, конфигурация и ответы baseline, конфигурация судьи и три отчёта аудита. Совпадающие файлы не скачиваются повторно. При конфликте общих контрольных файлов выполнение останавливается; изменяемые файлы v3 предварительно сохраняются в резервную копию.

В исходном третьем ноутбуке выходы направлены на Drive. Он сохранён как запись выполненного эксперимента. Для нового длительного запуска используется ноутбук 04 с прямым скачиванием архивов.

## Данные и проверки

```bash
python scripts/audit_sft_v3.py
python scripts/sync_colab_data.py --project-root . --verify-local
python -m unittest discover -s tests -v
```

Для намеренной пересборки v3:

```bash
python scripts/build_sft_v3.py
python scripts/update_v3_manifest.py
```

Сборщик пишет только в каталоги v3. Предыдущие данные и выполненные ноутбуки сохранены. Для экспорта отображённых результатов третьего ноутбука без его выполнения:

```bash
python scripts/export_notebook_evidence.py
```

Карточки датасетов описывают происхождение и ограничения; они не заменяют независимую экспертизу советов. PDF-отчёт в эту процедуру не входит.
