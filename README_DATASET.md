# Воспроизведение PlantAdvisor v3

## Опубликованный эксперимент

`notebooks/04_reproduce_v3.ipynb` содержит выполненный прогон на T4: 90 шагов, 2 эпохи, 30 ответов SFT и сравнение на 29 общих оценках судьи. Его 59 выводов сохранены. Веса, конфигурации, окружение, журнал и полные JSONL этого же прогона опубликованы; хеши входных данных совпадают с `data/v3/`.

Первый запуск сохранён отдельно в ноутбуке 03. Его адаптер не сохранился; таблицы и изображения с `notebook_` или `_notebook` извлечены из сохранённых выводов. Они относятся к первому прогону и не подменяют исходные файлы повторного запуска.

## Скачать готовые веса

В [GitHub Release](https://github.com/Batyaoftheyear/plant-advisor/releases/tag/stage1-v3-reproduction) доступны `plant_advisor_v3_reproduction_complete.zip` и `SHA256SUMS.txt`. В архиве находятся адаптер safetensors, токенизатор, данные, конфигурации, логи, ответы и оценки. Размер ZIP — 115 469 576 байт. Ссылки и контрольная сумма также сохранены в [метаданных публикации](results/reproduction_release.json).

Проверьте SHA-256 скачанного файла и распакуйте его в корень копии репозитория, сохраняя пути. Полный SHA-256:

```text
9ed68385ac0b0ac3025c5f78f825354d31117fff6d0479fb1ec6eb471ebc0443
```

Адаптер находится в `results/sft/qwen25_3b_qlora_dataset_v3_recovery/adapter/`. Для загрузки базовой модели используйте `base_model` и `base_revision` из соседнего `training_config.json`: `Qwen/Qwen2.5-3B-Instruct`, ревизия `aa8e72537993ba99e69dfaafa59ed015b17504d1`. Токенизатор загружайте из каталога адаптера. Поле `revision` в автоматически созданном `adapter_config.json` равно `null`, поэтому ревизию базы необходимо указать явно. Версии библиотек и способ 4-битной загрузки приведены в ноутбуке 04.

## Повторить обучение и оценку

[Откройте 04_reproduce_v3.ipynb в Google Colab](https://colab.research.google.com/github/Batyaoftheyear/plant-advisor/blob/main/notebooks/04_reproduce_v3.ipynb).

1. Выберите T4 и выполните ячейки по порядку. Если установка библиотек потребует перезапуска, перезапустите среду и начните выполнение заново.
2. В окне `drive.mount` разрешите подключение Google Drive. GitHub и исходные модели общедоступны; секреты в коде не используются.
3. Сохраните `plant_advisor_v3_reproduction_training.zip`, который скачивается после обучения и построения loss. В нём уже находятся `adapter_model.safetensors`, `adapter_config.json`, конфигурация и журналы.
4. После оценки сохраните `plant_advisor_v3_reproduction_complete.zip`. Он дополнительно содержит 30 SFT-ответов, оценки судьи, таблицы и графики. Для сравнения с опубликованным запуском проверяйте метрики и происхождение нового архива отдельно.

Выходы записываются в `/content/plant-advisor-v3-reproduction/`, подкаталоги `results/sft/qwen25_3b_qlora_dataset_v3_recovery/` и `results/evaluation/qlora_dataset_v3_recovery/`. Старые эксперименты не заменяются. Локальный диск Colab временный: ZIP необходимо сохранить на компьютере до завершения сеанса.

Экспорт выполняется `scripts/export_submission_artifacts.py`. Перед упаковкой проверяются наличие адаптера и согласованность данных с конфигурацией. В ZIP включаются контрольные суммы; промежуточные checkpoints и состояния оптимизатора не включаются.

## Входные файлы

Синхронизация использует один SHA коммита и `data/v3/manifest.json`. Загружаются пять файлов v3, контрольные вопросы, конфигурация и ответы baseline, конфигурация судьи и три отчёта аудита. Совпадающие файлы не скачиваются повторно. При конфликте общих контрольных файлов выполнение останавливается; изменяемые файлы v3 предварительно сохраняются в резервную копию.

В исходном третьем ноутбуке выходы направлены на Drive. Он сохранён как запись выполненного эксперимента. Для нового длительного запуска используется ноутбук 04 с прямым скачиванием архивов.

## Данные и проверки

```bash
python scripts/audit_sft_v3.py
python scripts/sync_colab_data.py --project-root . --verify-local
python -m unittest discover -s tests -v
```

Для намеренной пересборки v3:

```bash
python scripts/build_sft_v3.py
python scripts/update_v3_manifest.py
```

Сборщик пишет только в каталоги v3. Предыдущие данные и выполненные ноутбуки сохранены. Для экспорта отображённых результатов третьего ноутбука без его выполнения:

```bash
python scripts/export_notebook_evidence.py
```

Карточки датасетов описывают происхождение и ограничения; они не заменяют независимую экспертизу советов. PDF-отчёт в эту процедуру не входит.
